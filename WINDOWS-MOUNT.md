# Mount на Windows без WinFsp

Дата проверки: 19.04.2026

> **Статус: реализовано** по варианту 2 (собственный WebDAV внутри
> `restlex-agent`). Как это работает в текущей сборке — раздел
> «Как это устроено сейчас» в конце файла; всё, что выше, — исходное
> исследование, оно оставлено как обоснование выбора.

## Что показал `restic/restic#4754`

- PR `#4754` открыт с `06.04.2024`, заголовок: `Add WebDAV server (ie "mount" on Windows)`.
- Это не драйвер и не FUSE для Windows.
- Идея PR: добавить в `restic` read-only команду `webdav`, которая поднимает локальный WebDAV-сервер и даёт открыть снапшоты через проводник Windows.
- В патче Windows открывается через путь вида `\\127.0.0.1@3080\DavWWWRoot`.
- Автор прямо пишет, что это черновик: нет тестов, нет документации, есть замечания по конкурентности, путям и производительности.
- Участник `fd0` из команды restic в комментарии `11.04.2024` подтвердил, что направление правильное, но нужен рефакторинг общего виртуального FS-слоя, чтобы его могли использовать `fuse`, `webdav` и будущий web UI.

## Что это значит для Restlex

- WinFsp нам больше не нужен.
- Собственный драйвер или FUSE-слой для Windows делать не надо.
- Правильный путь для Windows mount: локальный loopback WebDAV.
- Это даёт просмотр снапшотов в Explorer без установки драйверов и без букв дисков.

## Рекомендуемая реализация у нас

### Вариант 1. Предпочтительный

Когда upstream `restic` добавит `webdav`, Restlex должен:

1. запускать `restic webdav 127.0.0.1:случайный_порт`;
2. открывать Explorer на `\\127.0.0.1@порт\DavWWWRoot`;
3. уметь останавливать процесс WebDAV;
4. показывать статус mount в GUI.

Плюсы:

- без WinFsp;
- без своего файлового драйвера;
- меньше собственного кода;
- совместимо с тем, куда сам идёт restic.

### Вариант 2. Если нужно раньше, чем это появится в upstream restic

Делать mount через нашу службу `restlex-agent`, а не через Python GUI.

Служба должна:

1. поднимать локальный read-only WebDAV-сервер только на `127.0.0.1`;
2. отдавать дерево снапшотов и чтение файлов из репозитория;
3. держать один активный mount-процесс на профиль;
4. отдавать GUI статус, порт и путь для открытия в Explorer;
5. завершать mount по кнопке "Отключить" или по таймауту простоя.

Почему именно служба:

- mount не должен жить внутри GUI-процесса;
- GUI можно закрыть, а доступ должен корректно завершаться отдельно;
- туда же потом ляжет автообновление и внешний контроль.

## Что важно учесть

- Текущая документация restic всё ещё говорит, что `restic mount` через FUSE доступен только на Linux, macOS и FreeBSD.
- Значит, возвращать старую кнопку `mount` через `restic mount` на Windows нельзя.
- WebDAV-клиент Windows может агрессивно обходить каталоги, поэтому нужен ленивый обход дерева и кэш метаданных.
- Для первого этапа лучше делать только чтение.
- Аутентификация для localhost-монта на Windows отдельная тема. На старте проще и надёжнее bind только на `127.0.0.1` и не светить сервер наружу.

## Вывод

Для Windows нам нужен не новый WinFsp-слой, а `WebDAV mount` через локальный сервер.

Практический план:

1. держим просмотр/восстановление через текущую вкладку как основной путь;
2. mount возвращаем только как WebDAV;
3. реализацию mount встраиваем в `restlex-agent` либо переключаемся на upstream `restic webdav`, когда он появится.

## Как это устроено сейчас

Реализовано в `rust/crates/restlex-agent/src/mount.rs`, управление —
`GET /mount/status`, `POST /mount/start/:pid`, `POST /mount/stop`
(маршруты требуют Bearer-токен, см. `REST_API.md`).

### Адрес и привязка

- Сервер слушает **только `127.0.0.1`** на свободном порту. Раньше был bind на
  `0.0.0.0`: смонтированный снапшот означал, что весь репозиторий доступен на
  чтение любому хосту в сети.
- Имя хоста в UNC — **всегда `localhost`**: путь вида
  `\\localhost@<порт>\DavWWWRoot`. Раньше подставлялся `COMPUTERNAME`, но он
  резолвится в LAN-адрес, на который сервер больше не отвечает, и mount ломался.
- Один активный mount на всю службу: `start` для другого профиля сначала
  останавливает предыдущий.

### Авторизации нет — и не будет

Basic-аутентификации на WebDAV сознательно нет. Windows WebClient по умолчанию
имеет `BasicAuthLevel = 1` («Basic только поверх SSL») и по обычному HTTP креды
не отдаёт: `net use \\localhost@порт\DavWWWRoot` получал бы `401` и падал с
ошибкой 1244 у всех подряд. Роль защиты выполняет привязка к loopback —
слушатель недоступен из сети.

Следствия для клиента (GUI и любого другого):

- в `MountStatus` поля `username` и `password` **всегда `null`**;
- подключаться нужно `net use <UNC>` **без `/user:` и без пароля**;
- `note` в ответе: `Read-only WebDAV mount (localhost, без авторизации)`.

### Ответ `/mount/status`

`active`, `pid` (профиля), `profile_name`, `port`, `unc_path`, `started_at`
(RFC 3339), `note`, `username`, `password`.

### Прочее

- Доступ только на чтение.
- Перед стартом агент проверяет и при необходимости поднимает службу
  `WebClient` (на Windows Server она может быть не установлена — тогда GUI
  предлагает поставить компонент через DISM).
